# CSharpTasks

Решение набора задач на C# с акцентом не только на получение корректного результата, но и на структуру проекта, расширяемость, потокобезопасность и автоматическое тестирование.

Проект разработан на **C# / .NET 10**.

## Содержание

Решение включает три задачи:

1. Компрессия и декомпрессия строк.
2. Потокобезопасный сервер-счётчик.
3. Стандартизация лог-файлов.

Для проверки реализации используется отдельный проект автоматических тестов на **xUnit**.

## Задача 1 — компрессия и декомпрессия строк

Реализованы алгоритмы компрессии и декомпрессии строк, состоящих из строчных букв латинского алфавита.

Последовательно идущие одинаковые символы заменяются символом и количеством его повторений.

Если символ встречается в группе только один раз, количество не записывается.

### Пример

Исходная строка:

aaabbcccdde

После компрессии:

a3b2c3d2e

После декомпрессии:

aaabbcccdde

Реализация поддерживает группы длиной больше 9:

aaaaaaaaaaaa -> a12

Для работы со строками используется `StringBuilder`, что позволяет избежать создания большого количества промежуточных объектов `string`.

Также выполняется проверка входных данных.

Основные классы:

Tasks/Task1/
  StringCompressor.cs
  StringDecompressor.cs

## Задача 2 — потокобезопасный сервер

Реализован статический класс `CountServer`, предоставляющий методы:

GetCount()
AddToCount(int value)

Для синхронизации используется:

ReaderWriterLockSlim

Реализация обеспечивает следующие свойства:

- несколько читателей могут одновременно получать значение `count`;
- запись выполняется только одним потоком одновременно;
- во время записи читатели ожидают её завершения;
- параллельные операции записи не приводят к потере обновлений.

Например, выполнение 1000 конкурентных операций:

AddToCount(1)

приводит к увеличению счётчика ровно на:

1000

Блокировки освобождаются через `finally`, что гарантирует их освобождение даже при возникновении исключения.

Основной класс:

Tasks/Task2/
  CountServer.cs

## Задача 3 — стандартизация лог-файлов

Консольное приложение умеет обрабатывать лог-файл, содержащий записи двух различных форматов.

### Входной формат 1

10.03.2025 15:14:49.523 INFORMATION Версия программы: '3.4.0.48729'

### Входной формат 2

2025-03-10 15:14:51.5882| INFO|11|MobileComputer.GetDeviceId| Код устройства: '@MINDEO-M40-D-410244015546'

Оба формата преобразуются во внутреннюю модель `LogEntry`, после чего записываются в единый выходной формат.

Поля выходной записи разделяются символом табуляции:

Дата	Время	Уровень	ВызвавшийМетод	Сообщение

Пример:

10-03-2025	15:14:49.523	INFO	DEFAULT	Версия программы: '3.4.0.48729'

### Нормализация уровней логирования

| Входное значение | Выходное значение |
| `INFORMATION` | `INFO` |
| `INFO` | `INFO` |
| `WARNING` | `WARN` |
| `WARN` | `WARN` |
| `ERROR` | `ERROR` |
| `DEBUG` | `DEBUG` |

Если вызывающий метод отсутствует во входном формате, используется:

DEFAULT

Невалидные записи не попадают в основной выходной файл. Они сохраняются без преобразования в:

problems.txt

### Обработка больших файлов

Входной файл обрабатывается построчно с помощью `StreamReader`.

Поэтому для обработки не требуется предварительно загружать весь лог-файл в оперативную память.

### Расширяемость

Для парсеров используется интерфейс:

ILogParser

Текущая реализация содержит:

FirstFormatLogParser
SecondFormatLogParser

Общий `LogParser` последовательно использует зарегистрированные парсеры.

Это позволяет добавить поддержку нового формата отдельным классом, реализующим `ILogParser`, без изменения существующих парсеров.

Структура третьей задачи:

## Формат даты

В текстовом описании задания выходной формат даты указан как:

DD-MM-YYYY

При этом приведённые в условии примеры выходных данных используют формат:

YYYY-MM-DD

В реализации приоритет отдан явно указанному требованию `DD-MM-YYYY`.

Например:

10-03-2025

## Тестирование

Для автоматического тестирования используется **xUnit**.

Тестами покрываются:

- компрессия строк;
- декомпрессия строк;
- группы длиной больше 9;
- некорректные входные данные;
- цикл `Compress -> Decompress`;
- чтение и изменение потокобезопасного счётчика;
- конкурентная запись;
- одновременная работа читателей и писателей;
- первый формат логов;
- второй формат логов;
- нормализация уровней логирования;
- невалидные лог-записи;
- форматирование выходных данных;
- обработка файлов.

Также присутствует интеграционный тест, создающий временный входной файл и проверяющий содержимое сформированных `output.txt` и `problems.txt`.

## Запуск программы

### Visual Studio

Открыть:

CSharpTasks.slnx

Выбрать проект `CSharpTasks` в качестве запускаемого и запустить приложение.

### Через .NET CLI

Из корневой директории:

dotnet run --project CSharpTasks

После запуска доступно меню:

CSharp Tasks
1 - String compression/decompression
2 - Thread-safe server
3 - Log file standardization
0 - Exit
